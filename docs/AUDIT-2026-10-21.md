## Implementation Integrity Verdict

**ผ่านด้านความสอดคล้องของระบบผลิตภัณฑ์ แต่ยังไม่ผ่านการตรวจ accessibility ในขอบเขตที่ทดสอบ** UI ใช้ชุดไอคอนเดียวกัน มี tokens Light/Dark และรูปแบบการทำงานที่เหมาะกับเครื่องมือเปรียบเทียบไฟล์ ไม่พบเหตุผลให้เปลี่ยนระบบภาพทั้งชุด ปัญหาหลักเป็นช่องว่างของ semantics, สีใน Monaco และการจัด layout ของ Files

## Findings ตามความรุนแรง

### A01 · P1 · สีข้อความใน editor ไม่ผ่าน contrast บนพื้น diff

- หมวด: Accessibility / Theming
- ตำแหน่ง: `src/renderer/theme.ts:48` และ `src/renderer/theme.ts:74` — กำหนดพื้น diff แต่ปล่อย `rules: []` ให้สืบทอดสี syntax
- ยืนยัน: Files Light พบข้อความสี `#778899` บน `#ffe3e3` ประมาณ **3.0:1** และสี `#ff0000` ประมาณ **3.3:1**; Dark พบ comment `#608b4e` บน `#1e2228` ประมาณ **4.0:1**, token `#778899` บน `#542b32` ประมาณ **3.3:1** และสี `#ff0000` ประมาณ **3.0:1** โดย detector ตรวจ background overlay ของ diff ด้วย
- ผลกระทบ: ข้อความและค่าที่เปลี่ยนซึ่งเป็นเนื้อหาหลักอ่านยาก โดยเฉพาะผู้มีสายตาเลือนราง
- มาตรฐาน: [WCAG 1.4.3 Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) กำหนด 4.5:1 สำหรับข้อความขนาดปกติ
- แนะนำ: ปรับ token foreground และพื้น diff เป็นชุดเดียวกัน ตรวจทั้งพื้นปกติ, changed line, changed character และ selection โดยรักษาความหมายของสี syntax
- คำสั่ง: `$impeccable harden`
- หลักฐาน: `evidence/audit-2026-10-21/detector-files-light.json`, `detector-files-dark.json`, `files-light-native.png`, `files-dark-native.png`

### A02 · P1 · ช่องเลือกภาษาไม่มี accessible name และฟอร์มไม่ระบุฝั่งชัดเจน

- หมวด: Accessibility
- ตำแหน่ง: `src/renderer/index.html:42`, `:48`, `:53`, `:59`
- ยืนยัน: `.lang` ทั้งสองช่องไม่มี label, `aria-label` หรือ `aria-labelledby`; accessibility snapshot แสดง `combobox:` ว่างทั้งคู่ Path ทั้งสองใช้ placeholder เดียวกัน และปุ่ม Open มีชื่อเป็น emoji ใน accessibility tree
- ผลกระทบ: ผู้ใช้โปรแกรมอ่านหน้าจอไม่ทราบว่ากำลังเลือกอะไรหรือแก้ฝั่งใด เพิ่มความเสี่ยงต่อการทำงานผิดด้าน
- มาตรฐาน: [WCAG 4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html)
- แนะนำ: ให้ชื่อที่ระบุทั้งหน้าที่และฝั่ง เช่น Left file path, Right language, Open left file และ Save right file ใช้ label ที่ผูกกับ control หรือ ARIA ตามความเหมาะสม
- คำสั่ง: `$impeccable harden`
- หลักฐาน: `files-dark-native.aria.txt`, `files-dark-native.json` ในโฟลเดอร์หลักฐานของ audit

### A03 · P1 · ข้อผิดพลาดของ Files ไม่ถูกประกาศเป็น status message

- หมวด: Accessibility
- ตำแหน่ง: `src/renderer/index.html:67`, `:70`; `src/renderer/main.ts:39`
- ยืนยัน: กรอก path ที่ไม่มีอยู่จริงแล้วกด Enter เกิดข้อความ Cannot open … (os error 2) ที่ `#st-msg` แต่ตัวข้อความและบรรพบุรุษใน statusbar ไม่มี live semantics และ focus อยู่ที่ช่อง path
- ผลกระทบ: ผู้ใช้โปรแกรมอ่านหน้าจออาจไม่ทราบว่าการเปิดไฟล์ล้มเหลว แม้เห็นข้อความบนจอ
- มาตรฐาน: [WCAG 4.1.3 Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)
- แนะนำ: แยก status ของคำสั่งและข้อผิดพลาดออกจากตำแหน่ง cursor ใช้ `role=status`/live region และ alert ตามระดับความเร่งด่วน เพื่อไม่ประกาศทุกครั้งที่ cursor ขยับ
- คำสั่ง: `$impeccable harden`

### A04 · P1 · คำสั่ง Files หลุดขอบเมื่อหน้าต่างแคบ

- หมวด: Responsive Design
- ตำแหน่ง: `src/renderer/styles.css:199`, `:368`, `:371`
- ยืนยัน: ที่ viewport 640×480 CSS px ปุ่ม Reload อยู่ x=641–697, Rules x=699–755 และ History x=757–813 จึงหลุดขอบ ขณะที่ body ไม่เปิดการเลื่อนแนวนอน; document scrollWidth เท่ากับ 960 ทั้งที่ viewport 640 และพบ overflow ของส่วนหัวที่ 900 CSS px เช่นกัน
- ผลกระทบ: เข้าถึง Rules/History ด้วยเมาส์ไม่ได้ในหน้าต่างแคบ และ metadata ฝั่งขวาบางส่วนถูกตัด ต้องขยายหน้าต่างหรือไล่ focus เพื่อหาคำสั่ง
- มาตรฐาน: ข้อบกพร่องการใช้งานเมื่อปรับขนาดหน้าต่าง ยังไม่ได้ทดสอบ browser zoom/text scaling ครบเพื่อสรุปผล WCAG Reflow อย่างเป็นทางการ ไม่ถือ horizontal scroll ภายในตาราง Folders เป็นข้อผิดพลาดโดยตัวมันเอง
- แนะนำ: จัด overflow/More ให้ Files ตามรูปแบบ Folders หรือให้กลุ่มคำสั่ง wrap ได้จริง และใช้ `minmax(0, 1fr)`/ขอบเขตย่อส่วนหัวที่เหมาะสม ตรวจให้ปุ่มและ metadata ที่จำเป็นยังเข้าถึงได้
- คำสั่ง: `$impeccable adapt`
- หลักฐาน: `files-light-640.png`, `files-light-640.json`, `files-light-900.json`; เปรียบเทียบ `folders-light-640.png`

### A05 · P1 · semantics ของ treegrid ไม่ตรงกับจำนวนคอลัมน์ที่ประกาศ

- หมวด: Accessibility / Implementation Integrity
- ตำแหน่ง: `src/renderer/folderView.ts:94`, `:232`, `:595`, `:635`, `:681`
- ยืนยัน: ประกาศ `aria-colcount=7` แต่ header มี 6 columnheaders และแต่ละแถวมีเพียง 3 gridcells; Name/Size/Modified อยู่ภายใน cell ใหญ่เดียวต่อฝั่งโดยไม่มี colspan หรือ colindex อธิบาย mapping
- ผลกระทบ: โปรแกรมอ่านหน้าจอไม่สามารถจับคู่หัวคอลัมน์กับค่าฝั่งซ้าย/ขวาอย่างเชื่อถือได้ แม้ภาพบนจอดูเป็น 7 คอลัมน์
- มาตรฐาน: WCAG 1.3.1 / 4.1.2 และโครงสร้าง ARIA grid; ดู [WAI-ARIA treegrid](https://www.w3.org/TR/wai-aria-1.2/#treegrid)
- แนะนำ: ทำ header/cell structure ให้ตรงกับคอลัมน์จริง รวมคอลัมน์สถานะ หรือกำหนด span/index ให้สอดคล้องกับข้อมูลที่ประกาศ รักษา virtualization และ active-descendant เดิม
- คำสั่ง: `$impeccable harden`
- หลักฐาน: `folders-dark-native.json`, `folders-dark-native.aria.txt` — 7 entries, 8 rows รวม header, 3 cells ต่อแถว

### A06 · P1 · การปรับขนาดคอลัมน์ยังใช้คีย์บอร์ดไม่ได้ และ splitters ไม่รายงานค่า

- แนะนำ: ให้ column resize มีทางเลือกผ่านคีย์บอร์ด เพิ่ม role/name/orientation และค่าปัจจุบัน/ช่วงค่าของ separator ที่โฟกัสได้ อัปเดตค่าเมื่อทั้ง pointer และ keyboard เปลี่ยนขนาด

## Patterns และสิ่งที่ควรรักษา

รูปแบบปัญหาที่ซ้ำกันคือเพิ่ม semantic state ให้ toolbar ได้ แต่รายละเอียดภายใน file headers, statusbar และ grid ยังไม่ครบ อีกส่วนคือ theme ของ shell กับ token สีใน Monaco ใช้คนละระดับ จึงต้องตรวจสีบน diff overlays ด้วย

สิ่งที่ตรวจแล้วทำงานได้:

- Files/Folders ใช้ icon family และ tokens ร่วมกัน Light/Dark เปลี่ยนได้จริงใน native app
- Folders มีชื่อ path แยกฝั่ง, progress แบบ `role=status`, summary แบบ live region และสถานะมีทั้งสัญลักษณ์/ชื่อ ไม่ใช้สีอย่างเดียว
- ArrowDown ใน folder treegrid เปลี่ยน active descendant จาก row 2 เป็น row 3 ได้
- แท็บสลับด้วย Ctrl+Tab ได้ มีชื่อปุ่มปิดและเพิ่มแท็บ และ dialogs ที่ตรวจใช้ native `<dialog>`; Rules/History/Filters เปิดและปิดด้วย Escape ได้
- Folders ที่ 640 CSS px ยังแสดงคำสั่งครบ มี More และ scroll ภายในตาราง
- ทดสอบ touch สังเคราะห์ผ่าน Chromium CDP ที่ pane divider: ขยับจาก 50% ไป 52.5%, ขยับกลับ 50% แล้ว touchCancel ล้าง pointermove สำเร็จ ไม่พบการลากค้างในลำดับนี้ ดู `touch-gesture.json`
- Folder rows ใช้ virtualization และ requestAnimationFrame; มี language workers สำหรับ Monaco ไม่ควรถือ bundle ของ editor ว่าไม่จำเป็นทั้งหมด

## ขอบเขตหลักฐานและข้อจำกัด

- Native baseline: WebView2, viewport 1400×900 CSS px, ภาพ 2800×1800 pixels ที่ DPR 2; หน้าต่างรายงาน visibility เป็น visible
- ขนาด 900×650 และ 640×480 ใช้ CDP viewport emulation ใน WebView2 เดียวกัน ไม่ใช่การเปลี่ยน Windows DPI หรือทดสอบจอ/อุปกรณ์จริงหลายชนิด
