# Structural Compare (JSON / XML / CSV) — Design

วันที่: 2026-11-02 · สถานะ: รออนุมัติ

## เจตนาและเหตุผล

ไฟล์ config ที่เปรียบเทียบบ่อย (JSON, XML, CSV) มักต่างกันแค่รูปแบบ: ลำดับ key สลับ, การย่อหน้า, ช่องว่าง, `<a/>` กับ `<a></a>`, ตัวคั่น CSV, quote ที่ไม่จำเป็น Text diff จึงเต็มไปด้วยความต่างที่ไม่มีความหมาย ผู้ใช้อยากเห็นเฉพาะความต่างของ **ข้อมูลจริง**

วิธี: แปลงทั้งสองฝั่งเป็นข้อความ canonical (จัดรูปมาตรฐาน) แล้วเปิดเป็นแท็บเปรียบเทียบใหม่แบบ read-only ผู้ใช้ตกลงแล้วว่า **เลขบรรทัดในแท็บนี้ไม่ต้องตรงกับไฟล์ต้นฉบับ**

## Goals

- ปุ่ม/คำสั่ง **Structural** บน toolbar โหมด Files เปิดแท็บเทียบ canonical text ของสองฝั่ง
- รองรับ JSON, XML, CSV (ทำเรียงตามนี้ แต่ละเฟสใช้งานได้ในตัวเอง)
- ใช้ข้อความ **ปัจจุบันใน editor** (รวมที่ยังไม่บันทึก) ไม่ใช่ไฟล์บนดิสก์
- ใช้เครื่องมือเดิมได้ครบ: Prev/Next diff, All/Diffs/Context, Wrap, ค้นหา
- ไฟล์ต้นฉบับและแท็บต้นฉบับไม่ถูกแตะเลย

## Non-goals

- ไม่ map ความต่างกลับไปเลขบรรทัดต้นฉบับ
- ไม่แก้ไข/บันทึก/copy section ในแท็บ structural (read-only; แก้ที่แท็บต้นฉบับ)
- ไม่รองรับ YAML, JSONC (comment/trailing comma), HTML
- ไม่มีตัวเลือก "เรียงลำดับ array" / "เรียงแถว CSV" ในรอบนี้ (ลำดับ array และแถวถือว่ามีความหมาย)
- ไม่ผสาน Regex rules เข้ากับแท็บ structural; ไม่เชื่อมกับโหมด Folders

## Anti-goals

- ต้องไม่เขียนทับหรือเปลี่ยน model/ไฟล์ต้นฉบับ แม้โดยอ้อม
- ห้ามแปลงแล้วทำให้ข้อมูลที่ต่างกันจริงดูเหมือนเท่ากัน (เช่น ตัดตัวเลขทศนิยม, ทิ้ง duplicate key เงียบๆ)
- ห้ามค้างหรือกิน memory ไม่จำกัดกับไฟล์ใหญ่

## Constraints

- Backend logic อยู่ใน library crate `o_compare_rust` โดยไม่พึ่ง Tauri; `commands.rs` เป็นแค่ adapter (ตาม CLAUDE.md)
- เพิ่ม API ใหม่ต้องแก้ครบ: `src/shared/…`, `platform.ts`, `tests/folder-platform.ts`, `src-tauri/examples/folder-workspace.rs`, `commands.rs`, `lib.rs` (generate_handler), `capabilities/main.json` (+ permissions ที่ build.rs/autogenerated สร้าง)
- ขนาดข้อความสูงสุด 10 MiB ต่อฝั่ง (เท่า `MAX_TEXT_BYTES` ของ comparison_rules)
- **working tree มีงานที่ยังไม่ commit ของผู้ใช้** ในไฟล์ที่ต้องแตะหลายไฟล์ (`commands.rs`, `lib.rs`, `capabilities/main.json`, `build.rs`, `folder-workspace.rs`, `platform.ts`, `folders.ts`, `folder-platform.ts`, `diffView.ts`, `main.ts`, `index.html`, `styles.css`, `package.json`) การแก้ต้องเป็นแบบเพิ่มเล็กๆ ห้าม stash/reset/revert และห้ามรวมงานของผู้ใช้เข้า commit โดยไม่ตั้งใจ

## Approaches ที่พิจารณา

| | แนวทาง | ข้อดี | ข้อเสีย |
|---|---|---|---|
| A | สวิตช์ Structural บนแท็บเดิม (สลับ model) | อยู่ที่เดิม | ต้องสลับ model ใน `DiffView` ที่ผูกกับ dirty/undo/watch เสี่ยงสุด และชนกับงานค้างใน `diffView.ts` |
| **B** | **เปิดแท็บใหม่ `[Structural]` จากเอกสาร virtual read-only** | **แยกจากโค้ดแก้ไขไฟล์ ใช้ diff tooling เดิมครบ มีแบบอย่างคือ `history://`** | **ไม่อัปเดตอัตโนมัติ ต้องกดซ้ำเพื่อ refresh** |
| C | แผงรายการ `$.a.b: 1 → 2` | อ่านง่ายสำหรับ config | UX คนละแบบ ต้องสร้างหน้าจอใหม่ทั้งหมด |

**ผู้ใช้เลือก B** (ตามคำแนะนำ) หมายเหตุที่พบระหว่างสำรวจ: pipeline `normalize_pair` + `RegexDiffAdapter` ใช้ซ้ำตรงๆ ไม่ได้ เพราะส่งเลขบรรทัดของข้อความที่ปรับแล้วไปไฮไลต์บน model ต้นฉบับ ใช้ได้เมื่อจำนวนบรรทัดไม่เปลี่ยนเท่านั้น

## การออกแบบ (B)

### Backend (Rust, library crate)

โมดูลใหม่ `src-tauri/src/structural.rs`:

```
pub enum Format { Json, Xml, Csv }
pub fn canonicalize(text: &str, format: Format) -> Result<String, String>
```

คำสั่ง Tauri `canonicalize_structural(text, format) -> String` เป็น adapter บางๆ (`spawn_blocking`) เรียกต่อฝั่งละครั้ง ข้อผิดพลาดคืนเป็น `AppError` code `STRUCTURAL_PARSE` พร้อมข้อความระบุบรรทัด:คอลัมน์ ฝั่งที่ผิดพลาดระบุโดย renderer

กติกา canonical:

- **JSON** (`serde_json`): key เรียงตามตัวอักษร (ค่าเริ่มต้นของ `Map`), pretty-print 2 ช่องว่าง, ลำดับ array คงเดิม, สิ้นสุดด้วย `\n` ตัวเลขใช้ feature `arbitrary_precision` เพื่อไม่ให้เลขใหญ่/ทศนิยมถูกปัดและ `1` กับ `1.0` ยังต่างกัน duplicate key: ตรวจเองและ **รายงานเป็น error** ไม่ให้ last-wins เงียบๆ
- **XML** (`quick-xml`): ตัด XML declaration และ comment, แปลง CDATA เป็น text, `<a/>` ≡ `<a></a>`, เรียง attribute ตามชื่อ, ตัด whitespace-only text ระหว่าง element, trim text ของ element ที่มี text, ลำดับ element คงเดิม, ย่อหน้า 2 ช่องว่าง, คง namespace prefix ตามต้นฉบับ
- **CSV** (`csv`): ตรวจตัวคั่น (`,` `;` tab) จากบรรทัดแรก, ตีความ quote แล้ว re-emit เป็นตัวคั่น `,` quote เฉพาะที่จำเป็น, line ending `\n`, ตัด BOM, แถวและคอลัมน์คงลำดับ, จำนวนคอลัมน์ไม่เท่ากันไม่ถือเป็น error

ตรวจขนาดเกิน 10 MiB ก่อน parse และคืน error ชัดเจน

### Renderer

- ปุ่ม `data-cmd="structural"` ใน `#toolbar` (ข้อความ "Structural") และ entry ใน `commands`
- ลำดับการทำงาน: อ่านข้อความจาก model สองฝั่งของแท็บที่ active → เลือก format (ดูด้านล่าง) → เรียก canonicalize ทั้งสองฝั่ง → สร้าง `FileData` เสมือน → `tabs.findPair(...) ?? tabs.create()` → `tabs.replace` ทั้งสองฝั่ง → `activate` (รูปแบบเดียวกับ `showHistory().compare` ใน `main.ts`)
- path เสมือน: `structural://<format>/<left|right>/<path ต้นฉบับเต็ม>` เช่น `structural://json/left/E:/a/config.json` (ลงท้ายด้วยชื่อไฟล์ เพราะป้ายแท็บและช่อง path ตัดส่วนท้ายมาแสดง) ฝั่งที่ยังไม่มีไฟล์ใช้ `structural://<format>/<side>/untitled-<SideState.id>/Untitled` ต้องมี `<side>` และ path เต็มเสมอ เพราะ `FileTabs.findDocument` จับคู่ด้วย `documentKey(path)` ถ้าสองฝั่งเป็น `config.json` คนละโฟลเดอร์แล้ว path เหมือนกัน จะได้ model ตัวเดียวและไม่เห็นความต่างเลย
- **Refresh**: กดซ้ำจากแท็บต้นฉบับ → `findPair` เจอแท็บ structural เดิม แต่ `FileTabs.replace` จะ **ใช้ document เดิมโดยไม่โหลดข้อความใหม่** ดังนั้นต้องเรียก `view.loadDocument(doc, file)` กับ document ที่ `replace` คืนมาทุกครั้งอย่างชัดเจน (ใช้ได้กับกรณีสร้างใหม่ด้วย: โหลดซ้ำข้อความเดิมไม่เสียหาย) และคงตำแหน่งเลื่อนไว้ตามที่ `replace` ทำอยู่
- เลือก format: (1) จากนามสกุลของไฟล์ฝั่งซ้ายและขวา (`json`; `xml`/`config`/`csproj`; `csv`/`tsv`) (2) ถ้านามสกุลฝั่งใดไม่รู้จัก (รวม Untitled) ให้ดูจากเนื้อหา: ขึ้นต้นด้วย `{`/`[` → JSON, `<` → XML, นอกนั้น → ไม่รู้จัก (CSV ไม่เดาจากเนื้อหา) (3) ฝั่งที่รู้จักแล้วกำหนด format ให้ฝั่งที่ไม่รู้จัก (4) ถ้าสองฝั่งได้ format ไม่ตรงกัน หรือยังไม่รู้จัก → แสดงข้อความสถานะ ไม่เปิดแท็บ ไม่มี picker เลือก format เอง (ดูหัวข้อ "ผู้สร้างตัดสินใจแทน")
- การเป็น read-only: ตอนนี้มีเช็ก `startsWith('history://')` กระจาย ~8 จุด (`main.ts`, `diffView.ts`) แทนที่ด้วย helper เดียว `isVirtualPath(path)` ที่ครอบทั้ง `history://` และ `structural://` (ผลคือ Save ปิด, copy section ปิด, ไม่ watch ไฟล์, ช่อง path อ่านอย่างเดียว) ป้ายแท็บเป็น `[Structural]` และช่อง path แสดง `… [Structural — read-only]`
- ภาษา syntax highlight ตามฟอร์แมต (`json`, `xml`, plaintext สำหรับ csv)
- คำสั่ง Reload/Swap ในแท็บ structural: Reload ไม่ทำอะไรพร้อมข้อความ "กด Structural ที่แท็บต้นฉบับเพื่อรีเฟรช"

### การจัดการข้อผิดพลาด

parse ไม่ผ่านฝั่งใดฝั่งหนึ่ง → ไม่สร้างแท็บ, status bar แสดง `Left: JSON parse error at line 3, column 5` (ฝั่งที่ผิด, บรรทัดตามข้อความต้นฉบับ) ข้อความว่างทั้งฝั่งถือเป็น error "ไม่มีเนื้อหา"

## เฟสการทำงาน

1. **JSON ครบวงจร**: โมดูล Rust + คำสั่ง + ปุ่ม + แท็บ virtual read-only + helper `isVirtualPath` + test ทั้งหมด
2. **XML**: เพิ่ม `quick-xml`, กติกา canonical, test
3. **CSV**: เพิ่ม `csv`, ตรวจตัวคั่น, test

## การทดสอบ

- Rust: `src-tauri/tests/structural.rs` ต่อ format: key สลับที่ → canonical เท่ากัน, ค่าต่าง → canonical ต่าง, duplicate key เป็น error, เลขใหญ่/ทศนิยมไม่เสียรูป, XML self-closing/attribute order/CDATA/whitespace, CSV ตัวคั่น/quote/BOM, เกิน 10 MiB เป็น error, ข้อความ error มีบรรทัด:คอลัมน์
- UI (Playwright + Edge, harness เดิมที่ใช้ Rust จริง): `scripts/test-structural-compare.mjs` พอร์ตใหม่ที่ไม่ซ้ำ (1422–1455 ถูกใช้แล้ว ให้ตรวจก่อนเลือก) ตรวจว่า key สลับไม่ขึ้นเป็น diff, ค่าต่างขึ้น, แท็บเป็น read-only, กดซ้ำแล้ว refresh แท็บเดิม, ต้นฉบับไม่ dirty, parse ผิดแสดงข้อความและไม่เปิดแท็บ เพิ่มเข้า `npm test` (`package.json`)
- `npm run typecheck` และ `npm run test:rust` ต้องผ่าน

## ผู้เขียนตัดสินใจแทน (my call — ผู้ใช้แก้ได้ตอนรีวิว)

ที่มา: คำถามจาก builder check รอบเดียว ตอบด้วยหลัก "ไม่ทำให้ความต่างจริงดูเหมือนเท่ากัน" ถ้าสงสัยให้คงไว้ ไม่ทิ้ง

**XML**
- ทิ้งเฉพาะ XML declaration และ comment; **คง** DOCTYPE และ processing instruction อื่นๆ ตามต้นฉบับ
- mixed content (element ที่มีทั้ง text และ child element): คง text ตามต้นฉบับ ตัดเฉพาะ text ที่เป็น whitespace ล้วน trim ปลาย text ของ element ที่ไม่มี child element เท่านั้น
- subtree ที่มี `xml:space="preserve"` ไม่แตะ whitespace เลย
- entity/char reference (`&amp;` กับ `&#38;`) ให้ parser decode แล้ว escape กลับแบบมาตรฐาน จึงถือว่าเท่ากัน
- `xmlns` คงเป็น attribute และเรียงรวมกับ attribute อื่นตามชื่อ ไม่ย้ายตำแหน่งการประกาศ

**CSV**
- บรรทัดว่างคงไว้เป็นแถวว่าง (`csv` crate ข้ามบรรทัดว่างโดยค่าเริ่มต้น ต้องตั้งค่าหรือประมวลผลเองเพื่อไม่ให้ความต่างหาย)
- แถวหัวตารางไม่พิเศษ ถือเป็นแถวธรรมดา

**ฟอร์แมตไม่ทราบ** — ไม่มี picker เลือกเอง ใช้นามสกุลแล้ว sniff เนื้อหา (JSON/XML) ตามหัวข้อ Renderer; ถ้าต้องการ picker หรือ sniff CSV ให้ระบุเป็นงานถัดไป

**ขีดจำกัด**
- 10 MiB วัดเป็น UTF-8 bytes ของข้อความจาก model ตามที่ `MAX_TEXT_BYTES` ทำอยู่
- เพดาน canonical output 64 MiB เกินแล้วเป็น error (pretty-print ขยายได้หลายเท่า)
- ไม่มี timeout ฝั่ง canonicalize เพราะงานเป็นเชิงเส้น; ส่วน diff อยู่ใน worker ของเดิมที่มี `maxComputationTimeMs: 3000` อยู่แล้ว
- ระหว่างทำงานแสดงสถานะ "Building structural view…" ใน status bar และกันกดซ้ำจนกว่าจะเสร็จ
