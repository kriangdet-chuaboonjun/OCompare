# Settings Implementation Plan

**Goal:** Move theme and manual update controls into Settings, accessible from an always-visible toolbar gear.

**Architecture:** Static accessible Settings dialog holds existing control IDs; a small initializer handles opening, closing and update handoff. Existing theme and updater services retain their handlers and persistence. Overflow measures comparison commands only.

**Tech Stack:** TypeScript, HTML, CSS, native dialog, existing Playwright/Rust fixture transport.

**Spec:** docs/superpowers/specs/2026-11-04-settings-design.md

## Constraints and review focus

- Preserve edits, active Files/Folders tabs and theme persistence.
- Settings must remain accessible at 640–1920px, even when overflow is present.
- Escape restores focus; workspace shortcuts must not run through Settings.
- Manual updates must reach the existing update flow and install guards.
- Adapt existing UI tests to reach relocated controls through Settings.
